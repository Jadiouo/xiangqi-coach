# 背景

整理日期 2026-10-06。這份文件是使用者跟另一個 AI 討論的結果，讓你知道每個決定是怎麼來的。使用者的原話用引號標出。

## 使用者

- Jadio（Lex），電機系大四，做機器人與狀態估計。熟 Python、C、C++、Linux；Rust 寫過一個語音輸入工具。
- 他平常不讀程式碼，看的是驗證後的結果。所以**測試、數字、進度紀錄是他判斷你做得好不好的唯一依據**，要寫得讓不看程式的人也看得懂。
- 他用語音輸入，文字裡會有同音字。

## 這個專案怎麼來的

他想找一個夠大、能讓 AI 自己做很久的題目，條件是「有標準答案可以對」。象棋引擎符合：走法產生有公認的 perft 數字，棋力可以用對打量。他在幾個候選裡選了這個，並指定要做中國象棋。

## 他要的東西（原話）

- 語言：「我想要用 rust 或是 c 加加寫」。→ 已決定用 Rust，理由見 SPEC 第 3 節。
- 覆盤：「下完結束之後，他可以跟我一起復盤，說我哪裡下的好，哪裡下的不好。」
- 勝率：「要有即時的……勝率的分析，就是比如說我下到第二步的時候，我的勝率是五十趴，但是我下到第五步的時候，勝率突然驟降到十趴。那我就會知道說我哪裡下的不好。然後要給我更好的選擇。」
- 推演：「覆盤之後還可以……假設我下這裡你會下哪裡，然後怎樣怎樣怎樣一直推演下去。」
- 筆記：「覆盤結束之後，可以給我一份筆記。筆記的想法的話，我還沒有想好要怎麼做。」→ 第一版的格式由 SPEC 第 9 節提案，這是**還沒定案**的部分。
- 匯入棋譜：「把其他的棋局……那個代號……從其他的棋局裡面複製過來，直接貼上去的話，那他也可以覆盤這盤棋。」
- 形式：「我希望它可以做成不只有網頁……可能變成一個 APP 或者之類的。但是我們可以先從網頁開始。」

## 討論時他回答的四個問題

1. **使用者的程度**：「要適配不同程度的人。就是你大概下幾局你會知道它的程度……要根據它的程度去給他不同的介紹，不同的講解。」→ 程式要自己估計程度，不是讓人選。
2. **講解怎麼產生**：選了規則模板。完全離線、不用任何 AI 服務。
3. **覆盤用誰的判斷**：可以外接強引擎。對弈用自己寫的；覆盤時可以另外載入 Pikafish 當第二意見。
4. **棋譜從哪來**：中文記譜、座標記譜與 FEN、東萍這類象棋網站、手機 App 的棋局，四種都要。

## 已經定下來的設計原則

- 引擎本體與畫面分開，引擎可以不開畫面自己對打。
- 不用神經網路評估，不需要顯示卡。他的顯示卡要留給別的事。
- 長將、長捉先用簡化規則，先求能下。
- 每一版引擎比前一版強多少，要有一張表記下來。
